# /src/decision — DECISION layer

Decision Engine: candidate generation, scoring, ranking (`24_TECHNICAL_ARCHITECTURE.md` §32–36, `13_RECOMMENDATION_ENGINE.md`). Получает подготовленные данные из ANALYSIS + KNOWLEDGE, не обходит базу самостоятельно.

## Task 8.1 — CANDIDATE_GENERATOR + CANDIDATE_SCORER + RANKING_ENGINE, первый шаг (`23_SYSTEM_ARCHITECTURE.md` §25–27, `21_DECISION_LOGIC.md` §9/§39–41)

Первая реальная реализация слоя. `candidateGenerator.ts` — кандидаты-форматы берутся из реально существующих `Content.contentType` пользователя, не из захардкоженного списка. `candidateScorer.ts` — сравнивает производительность каждого кандидата (формата) с личной нормой (Task 6.2, `scope: global`, не меняется) по каждой из трёх метрик отдельно; учитывает Pattern (Task 7.2) как контекстную пометку, не как отдельный фактор ранжирования. Только 3 из 9 документированных факторов CANDIDATE_SCORER реализованы (historical performance/сравнение с нормой/confidence) — честно, не притворяясь, что реализовано больше, см. `DECISIONS.md` D-0024. Результат — качественная метка (`label`), не выдуманное число (§40 NO FALSE PRECISION). `recommendationCandidates.ts` — оркестрация, read-only: **не пишет в `Recommendation`** — reasons/context/decision_version (`25_DATABASE_SCHEMA.md` §26/§28/§30) — следующий шаг.

## Task 8.2 — GOAL_FIRST/GOAL_PRIORITY (`21_DECISION_LOGIC.md` §6–8)

`goalFit.ts` — `determineGoalFit`: выбирает, какой из уже посчитанных per-metric рейтингов (Task 8.1) первичен для целей пользователя — выбор, не смешивание метрик в одну оценку (прямое продолжение D-0024). `Goal.priority` — первое реальное использование (меньшее число = выше важность, ранжированный список §7). Честные состояния `no_goals_defined`/`no_tracked_goals`, когда goal fit не может выбрать метрику — per-metric рейтинги всё равно возвращаются целиком. `saves`↔`saved` — явное сопоставление словоупотребления документа и реального имени метрики (D-0018), не совпадение строк напрямую. См. `DECISIONS.md` D-0025.

## Task 8.3 — персистентность решения (`25_DATABASE_SCHEMA.md` §26 RECOMMENDATIONS/§28 RECOMMENDATION_REASONS/§30 RECOMMENDATION_CONTEXT)

`recommendationPersistence.ts` — `createRecommendation`: закрывает цикл «решение → можно объяснить и найти позже» на уже готовых Task 8.1/8.2 кандидатах, не добирая остальные факторы скоринга (прямое требование Olga). Пишет `Recommendation` только когда goal fit реально выбрал метрику (`reason: 'goal_matched'`) — `goalId` обязателен в схеме, придумывать/выбирать цель по умолчанию при её отсутствии было бы тем самым молчаливым предположением, которое запрещено ещё с Task 8.2. `RecommendationReason` — отдельная таблица (§28 даёт явный список колонок): `goal`/`baseline`/`pattern`(если направление совпало) — `weight` не заполняется, числового веса ни у одного фактора нет (§40 NO FALSE PRECISION). `context` — JSON-снимок на `Recommendation` (§30 не даёт список колонок, описан как единственный снимок, не список строк). `DECISION_VERSION` — первое реальное значение `decisionVersion`. Append-only (как `Memory`, не upsert как `Pattern`) — каждый вызов создаёт новую строку. См. `DECISIONS.md` D-0026.

## Task 8.4 — freshness + repetition (`21_DECISION_LOGIC.md` §12 FRESHNESS_WEIGHT/§13 RECENCY_OVERRIDE/§14 REPETITION_CONTROL)

`candidateScorer.ts` дополнен двумя качественными сигналами на `CandidateResult`, не влияющими на порядок ranking (тот же принцип §40, что Pattern/goal fit): `freshness` — метка по буквальным порогам §12 (0–3/3–6/6+ месяцев → recent/aging/stale) от самой свежей публикации кандидата; `repetitionNote` — заполняется только на топ-кандидате, только когда он совпадает с последним опубликованным форматом (`candidateGenerator.mostRecentContentType`) И есть конкурентная альтернатива (§13–14 — один механизм, не два). FRESHNESS_WEIGHT как decay-переоценка самого `computeBaseline` (Task 6.2) сознательно НЕ реализован — затронул бы ANALYSIS layer, отдельная будущая задача. `recommendationPersistence.ts` дополнен `reasonType: 'freshness'` (реальный пункт словаря §28); `repetitionNote` НЕ становится формальной причиной — «repetition» отсутствует в словаре `reasonType`, который даёт сам документ. См. `DECISIONS.md` D-0027.

`RECOMMENDATION_CANDIDATES` (§27) и `RECOMMENDATION_EVIDENCE` (§29), risk/opportunity (нужен «experimental candidate»/hypothesis status, `Experiment`-модель по-прежнему не используется), возможное числовое смешивание — не входят, открытые задачи Phase 8.
